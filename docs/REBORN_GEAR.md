# Gear & Difficulty Analyzer

Open **Survivor UI → Global → Open Gear & Difficulty**, use `/sui gear`, or open **Upgrades** in the native character window. In Dalaran choose a Campaign map and difficulty for a theoretical preview. Unlock status is unavailable. The tool uses your current class and actual equipped items in both views. In Campaign it follows the real map and tier. Hover an equipped slot in the native window for its next-star and next-tier previews.

Use **Set 100% Baseline** on a familiar configuration for each class. The addon stores the selected theoretical Dalaran target or live Campaign map and tier, baseline origin, applicable modifiers, actual equipped items, modeled values and game/data provenance. A manual Dalaran baseline is a personal reference. A later selection leaves the saved configuration in place until you use **Update 100% Baseline**. Compatible inputs are reevaluated under the current model, including legacy raw references that have no origin field. Uninterpretable configurations remain stored with an explanation. Legacy map-only references and cached gear stay outside the live analysis.

The two tabs share the effects panel and calculation. In **Difficulty & Upgrade Planner**, the A/B summaries show the selected variants and applicable target, budget, price and acquisition limits. Edit the target output percentage and optional whole-gold budget, then use **Calculate Plan** or press Enter in either field to apply both. Pending or invalid inputs leave the committed target and budget visible. Reset enters 100% in the target field for the next submission. Escape restores the focused field's committed value. A blank budget permits unrestricted planning. Zero gold permits only configurations with zero calculable star cost. Automatic account balance detection is unavailable. Set protection starts enabled. Turning it off may sacrifice important set effects outside the modeled output.

**Economy** opens first for both plans. **Max Gear** shows the quality and star ceiling independently of the budget. **Execution order** replaces the equipment list with the selected configuration's ordered actions, prerequisites, recalculated output and accumulating star quote. **Show full equipment** adds unchanged items. **Load in Simulator** copies the selected variant into the separate draft. In **Equipment Simulator**, change qualities and stars in the equipment pane while results update alongside it. Use **Reset to Actual Equipment** or a completed plan as a new starting point. Acquisition notes are beside the relevant item. **Show details** leads to model and price assumptions. The two panes scroll independently while context and pressure remain pinned. Narrow windows stack the panes.

The plan and simulator change local previews only. In a Campaign, open the analyzer over the native pause menu. Escape dismisses an open selection list first, then the analyzer, leaving the pause menu in place. The native character panel retains its own tooltip. The analyzer's own gear previews use a separate opaque tooltip.

## Data contracts

- `AZSZONE` supplies the current world key, class, `dt`, `heroic`, and reported modifiers. A recognized live non-hub Campaign key and consistent difficulty are required for comparison. Dalaran uses the manually selected map and modeled difficulty. The selector enumerates the pinned public Campaign catalog and displays the native localized names when present. The standard tier model is validated for each selected map and can honor a narrower map-specific cap in the catalog. No account unlock is inferred from a valid theoretical tier.
- The native addon requests `sync` on world entry. `AZSARMOR` supplies the equipped list after `AZSZONE`, including slot, rarity, stars and native descriptions. An explicit empty list is valid. The installed `Units.lua` notes that a fully unequipped hero may receive no list. Changed context invalidates the previous equipment. Equivalent events preserve it. Dalaran's **Refresh equipment** clears the worn snapshot before requesting the supported read-only sync. Native delivery immediately after equipping or upgrading gear in the hero menu awaits client verification. The armor line has no run ID, so a late older line arriving after a new valid zone event cannot be attributed by this interface.
- The hero menu is a separate Glue Lua environment. The documented World API and its native handlers provide no account collection, ascension permission, ascension price or post-ascension star state. The planner uses equipped gear and drop paths. The restriction for Legendary and higher includes clearing the final map of the next expansion. Dalaran cannot confirm an individual player's completion or eligibility.
- The original game paths are gated out. **Enable Gear & Difficulty** in Global settings controls the window and native previews. The native subscriptions have gated callbacks because `AZS.On` exposes registration only. Completed search results are cached for the current inputs. Enabling the feature in the world requests `sync`. An active diagnostic recording may also request one late `sync` under its existing rules.

## Equipment and pressure

For each item, sum `slot stat × tier slot scale` and `class profile stat × tier profile scale`, multiply by the catalog's common factor, then by `1 + min(stars, steps) × star_step + top_star_bonus`. Gear stats use fractions for percent shares and flat units for HP and regeneration. Both views group output, survival and utility attributes in actual, target and change columns. They show pre-rounding totals in percentages or flat units. Differences between percentages use percentage points. The native item display rounds HP per piece while the game adds the gear contribution before rounding.

Set thresholds come from `AZS_GEN.setRules` and matching class or shared rows from `AZS_GEN.setBonuses`. In the pinned content, four armor pieces at one star activate the four-piece effect, eight at three activate the eight-piece effect and eight at five empower eligible effects. Weapons are excluded. Verified unconditional shared four-piece gold, pickup, Echo and critical-damage modifiers appear in attributes. Spell-specific, conditional, or otherwise unquantified effects appear as set text. The solver protects active set effects with unquantified combat value.

| Quantity | Formula or source |
| --- | --- |
| Map output demand | Public zone base health factor × standard Campaign tier health factor. |
| Map survival demand | First boss base hit × standard Campaign tier hit factor. A representative early incoming hit. |
| Gear output capacity | `1 + sum of gear damage shares`. Neutral non-gear background and an ability affected by ordinary gear damage. |
| Gear survival capacity | `(class starting HP + flat gear HP) / (1 - min(gear damage reduction, 0.60))`. Standard cap under neutral non-gear assumptions. |
| Each pressure | `100 × target demand / baseline demand × baseline capacity / target capacity`. |

Standard tier multipliers are shared with Campaign analysis. The class-specific baseline is reevaluated from saved equipment and map data. The two formulas and the `0.000001` percentage-point tolerance at 100% continue to apply. The editable output target accepts finite values from 1% to 10,000%. The positive range keeps threshold division defined and covers wide differences between early and late maps. Budgets accept integers from 0 to 1,000,000,000, exactly representable by both supported Lua runtimes. Lower survival pressure describes a lower representative hit relative to effective health. The model excludes spawn density, encounter scripts, affix and challenge scaling, talents, regeneration, movement, crit, cooldown, Echo and special ability or summon behavior. The 60% cap excludes the Warrior Titan talent exception. Output comparisons can proceed if survival data are unavailable.

Named affixes and built-in Heroic rules qualify the calculation as standard Campaign pressure only, for either the baseline or target. The legacy `aff` field alone carries no named modifier evidence. An explicit unsupported mode, including active Proving Grounds, removes the pressure comparison and plans. When the native feed provides only a supported map and tier, the estimate remains scoped to ordinary Campaign pressure. Rift and Endless encounter mechanics are outside that estimate.

## Plans and gold

Plan A retains and upgrades worn pieces or uses higher-quality replacements from the target expansion's Campaign drops. Eligible drops of any quality can fill an empty slot. The manual simulator allows all legal qualities. The public zone table and documented pair/override rule determine standard tiers. The native tier catalog and pack assignment identify extra end-of-expansion tiers. A drop begins at zero stars for quoting. Replacement acquisition adds a separate gameplay requirement. Inventory ownership and its existing stars, direct ascension and slot-specific progression are unavailable. Plan B upgrades only worn items and tiers.

Equipment normalization, evaluation, previews, and optimization share the same class and slot contract. Native weapon layouts and class or tier weapon lists provide slot evidence. The stock layout retains known ranged and main-hand slots. An explicit pack-tier weapon list that lacks the relevant entry leaves that drop unverified for the slot. The documented Legendary appearance fallback applies when the class has no override. The simulator can still evaluate a legal theoretical class/slot/tier combination whose drop path is unverified.

A step to stars one through five costs `round(408 | 816 | 1496 | 2720 | 4080 × tier factor)`, rounded per step. The November 16, 2026 price chart's reduction is already in those base prices. Weapons use the same factors. Exotic, Elementium and Legendary's fifth star include formula-derived estimates. If a native factor differs from the verified schedule, the analyzer omits the unknown quote from the solver and indicates that the candidate was excluded. Gold shown for a replacement is the calculable amount spent on stars. No downgrade refund is assumed.

When actual gear meets the selected target, both plans recommend it at zero cost. Otherwise an unrestricted search computes the cheapest target configuration where possible. Economy minimizes pressure, then cost within the anchored tolerance, when the target is unreachable and the budget is blank. If the unrestricted result is too expensive or cannot reach the target, a separate bounded pass optimizes within the budget. It finds the least-cost qualifying setup or the best comparable output within budget, minimizing gold for equal output. Remaining cost ties minimize worn replacements and then new fills. The bounds combine set-constrained suffix damage and a relaxed gold-to-damage envelope. A cutoff, unpriced choice or unresolved acquisition path is disclosed separately. A proven star quote covers the modeled price and acquisition scope. See the [V1.1 review report](reviews/PR-007.md).

Max Gear uses the highest verified quality and maximum supported stars in Plan A, with the fewest lower-quality exceptions required to preserve active set thresholds. It chooses the greatest modeled output among those assignments, breaking exact ties in deterministic slot and option order. Plan B raises every worn item to the catalog ceiling and leaves empty slots alone. Max Gear can include legal upgrades with unknown quotes. The UI labels calculable gold and unknown portions separately. It reports the actual modeled result of the quality/star ceiling, which can differ from the Economy output optimum.

The native tooltip extension appends after the host sets the tooltip owner and validates the slot against the current world's equipped item. Simulator icons evaluate adjacent changes from the simulated loadout. Planned-item icons show item identity, intrinsic attribute changes and star/acquisition quotes. The effects pane shows complete equipment pressure, attributes and set effects. Tooltip ownership is released on relevant panel, slot or context changes. Hovering performs no combination search.

## Offline verification

Run the following with Python 3 and Lupa's Lua 5.1 runtime. Supply a trusted, locally accessible `Generated/Content.lua` from the game. The script executes that input as Lua. Use `--source-root` to compare the same data against an earlier checkout or source archive and `--repeat` to smooth CPU timing.

```text
python scripts/verify_reborn_gear.py --native-content <Generated/Content.lua> --repeat 7
python scripts/verify_reborn_gear.py --native-content <Generated/Content.lua> --recorded --repeat 7
python scripts/verify_reborn_gear.py --native-content <Generated/Content.lua> --gear-csv <independent-extraction.csv> --source-root <checkout>
```

The optional UTF-8 CSV has a header. Its first eight columns are tier key, star count, three extraction metadata columns, Warlock main-hand damage as a percentage, eight-armor-piece flat HP, and eight-armor-piece damage as a percentage. Supply values extracted independently of the planner. The verification compares the final three values at a tolerance of 0.00051 in their reported units, allowing a three-decimal reference. The benchmarks compare returned plan pressure and gold with the full public evaluator and check repeatability. Small-space optimum is checked separately by exhaustive enumeration in `tests/test_reborn_gear.lua`. Native game data, local expected CSV, and historical captures remain external.

Public balance data are pinned to `21071e86fee66ca7`. Native contract inspection, offline content comparisons, and the Campaign and Dalaran acquisition observations used Reborn 0.7.4. The full Campaign interaction, native tooltip rendering, and pause behavior of the revised window remain game-verification items.
