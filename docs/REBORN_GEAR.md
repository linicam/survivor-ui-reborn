# Gear & Difficulty Analyzer

**Historical reference.** The analyzer and simulator were built for the
pre-0.8.0 deterministic equipment system. They are suspended following the
random-loot overhaul. The addon manifest omits the legacy modules on all
clients. Existing preferences and baselines remain available as historical
data. Use the game's equipment interface for current gear.

## Historical workflow

Enter the Campaign map and difficulty you want to evaluate. Open **Survivor UI → Global → Open Gear & Difficulty** or use `/sui gear` in the world. The native character window's **Upgrades** button opens the same tool. Hover an equipped slot there for its next-star and next-tier previews. In Dalaran the tool opens directly to the Equipment Simulator with current equipment, quotes and set comparisons. Enter a Campaign for map comparisons and upgrade plans.

Use **Set 100% Baseline** on a familiar configuration for each class. The addon stores the actual map, tier, reported modifiers, equipped item identities, model inputs, active sets, game/data version and time. A later selection leaves the saved configuration in place until you use **Update 100% Baseline**. Compatible inputs are reevaluated under the current model, even when the server build or model version changes. The UI calls out changed modeled baseline values. Uninterpretable or unsupported configurations remain stored with an explanation. Legacy map-only references and cached gear are left on disk for compatibility and stay outside the live analysis.

The two tabs share the effects panel and calculation. In **Difficulty & Upgrade Planner**, compare the fixed A/B summaries and select a plan to see its changed gear beside the full configuration's output pressure, survival pressure, attributes and set effects. **Economy** opens first for both plans. A completed search with a proven unreachable target shows the least-cost configuration at the best priced output. A search limited by budget or evidence shows the best priced result so far and labels the uncertainty. Select **Max Gear** when available to inspect the verified quality and star ceiling as a reference. Each plan remembers its selection within the current comparison context. **Show full equipment** adds unchanged pieces to the list. **Load in Simulator** copies the selected variant into the separate draft. In **Equipment Simulator**, change qualities and stars in the equipment pane while results update alongside it. Use **Reset to Actual Equipment** or a completed plan as a new starting point. Acquisition notes are beside the relevant item. **Show details** leads to model and price assumptions. The two panes scroll independently while context and pressure remain pinned. Narrow windows stack the same independently scrollable panes.

The plan and simulator change local previews only. In a Campaign, open the analyzer over the native pause menu. Escape dismisses an open selection list first, then the analyzer, leaving the pause menu in place. The native character panel retains its own tooltip. The analyzer's own gear previews use a separate opaque tooltip.

## Data contracts

- `AZSZONE` supplies the current world key, class, `dt`, `heroic`, and reported modifiers. A recognized live non-hub Campaign key and consistent difficulty are required for comparison. The independently verified Campaign returned the active map and tier. Dalaran returned `dalaran` and Normal for the hub. The candidate settings readable from World Lua have insufficient freshness and encoding evidence for a Campaign lookup. The tool uses neither these settings nor a historical run to substitute a Campaign target.
- The native addon requests `sync` on world entry. `AZSARMOR` supplies the list of equipped items after `AZSZONE`, including slot, rarity, stars and the native item description fields. An explicit empty list is valid. The currently installed `Units.lua` documents that a hero wearing no equipment may receive no list, which the addon treats as unavailable. The module freezes normalized context fields. Replaced or in-place-mutated tables with a new identity invalidate the gear and search. Equivalent events preserve them. The armor line carries no run ID. A late older line that arrives after a new valid zone event cannot be attributed by this interface.
- The hero menu is a separate Glue Lua environment. The documented World API and its native handlers provide no account collection, ascension permission, ascension price or post-ascension star state. The planner uses equipped gear and drop paths. The restriction for Legendary and higher includes clearing the final map of the next expansion. Dalaran cannot confirm an individual player's completion or eligibility.
- The original game paths are gated out. **Enable Gear & Difficulty** in Global settings controls the window and native previews. The native subscriptions have gated callbacks because `AZS.On` exposes registration only. Completed search results are cached for the current inputs. Enabling the feature in the world requests `sync`. An active diagnostic recording may also request one late `sync` under its existing rules.

## Equipment and pressure

For each item, sum `slot stat × tier slot scale` and `class profile stat × tier profile scale`, multiply by the catalog's common factor, then by `1 + min(stars, steps) × star_step + top_star_bonus`. Gear stats use fractions for percent shares and flat units for HP and regeneration. Both views group output, survival and utility attributes in actual, target and change columns. They show pre-rounding totals in percentages or flat units. Differences between percentages use percentage points. The native item display rounds HP per piece while the game adds the gear contribution before rounding.

Set thresholds come from `AZS_GEN.setRules` and matching class or shared rows from `AZS_GEN.setBonuses`. In the pinned content, four armor pieces at one star activate the four-piece effect, eight at three activate the eight-piece effect and eight at five empower eligible effects. Weapons are excluded. Verified unconditional shared four-piece gold, pickup, Echo and critical-damage modifiers appear in attributes. Spell-specific, conditional, or otherwise unquantified effects appear as set text. The solver protects active set effects with unquantified combat value.

| Quantity | Formula or source |
| --- | --- |
| Map output demand | Public zone base health factor × standard Campaign tier health factor. |
| Map survival demand | First boss base hit × standard Campaign tier hit factor. A representative early incoming hit. |
| Gear output capacity | `1 + sum of gear damage shares`. Neutral non-gear background and an ability affected by ordinary gear damage. |
| Gear survival capacity | `(class starting HP + flat gear HP) / (1 - min(gear damage reduction, 0.60))`. Standard cap under neutral non-gear assumptions. |
| Each pressure | `100 × target demand / baseline demand × baseline capacity / target capacity`. |

Standard tier multipliers are shared with the Campaign analysis. The class-specific baseline is reevaluated from saved raw equipment and map data. The two formulas and the `0.000001` percentage-point tolerance at 100% continue to apply. Lower output pressure is the planning target. Lower survival pressure indicates a reduction in theoretical pressure from a representative incoming hit relative to effective health. It provides no death or clear-probability estimate. The model excludes spawn density, encounter scripts, affix and challenge scaling, talents, regeneration, movement, crit, cooldown, Echo and special ability or summon behavior. The 60% cap is the documented standard and excludes the Warrior Titan talent exception. Output comparisons can proceed if survival data are unavailable.

Named affixes and built-in Heroic rules qualify the calculation as standard Campaign pressure only, for either the baseline or target. The legacy `aff` field alone carries no named modifier evidence. An explicit unsupported mode, including active Proving Grounds, removes the pressure comparison and plans. When the native feed provides only a supported map and tier, the estimate remains scoped to ordinary Campaign pressure. Rift and Endless encounter mechanics are outside that estimate.

## Plans and gold

Plan A keeps the option to retain and upgrade worn pieces and includes replacement gear from the current expansion's Campaign drops. A drop can replace a worn item only at a higher quality. Eligible drops of any quality can fill an empty slot. The manual simulator continues to allow all legal qualities. The public zone table and documented pair/override rule determine standard tiers. The native tier catalog and pack assignment identify the extra end-of-expansion tiers. A drop begins at zero stars for quoting. Replacement acquisition adds a separate gameplay requirement. Inventory ownership and its existing stars, direct ascension and slot-specific account progression are unavailable. Plan B upgrades only the same items and tiers. The player balance does not restrict either search.

Equipment normalization, evaluation, previews, and optimization share the same class and slot contract. Native weapon layouts and class or tier weapon lists provide slot evidence. The stock layout retains known ranged and main-hand slots. An explicit pack-tier weapon list that lacks the relevant entry leaves that drop unverified for the slot. The documented Legendary appearance fallback applies when the class has no override. The simulator can still evaluate a legal theoretical class/slot/tier combination whose drop path is unverified.

A step to stars one through five costs `round(408 | 816 | 1496 | 2720 | 4080 × tier factor)`, rounded per step. The November 16, 2026 price chart's reduction is already in those base prices. Weapons use the same factors. Exotic, Elementium and Legendary's fifth star include formula-derived estimates. If a native factor differs from the verified schedule, the analyzer omits the unknown quote from the solver and indicates that the candidate was excluded. Gold shown for a replacement is the calculable amount spent on stars. No downgrade refund is assumed.

When the actual setup achieves 100% output pressure, both plans return it at zero cost. The optimizer uses exact set-constrained suffix maxima for additive gear Damage, a seed from the best priced suffix, and bounded depth-first enumeration with a relaxed gold bound. It minimizes calculable gold among output-qualified configurations. When no priced option meets the target, it minimizes output pressure, then gold within the anchored numerical tolerance. Gold ties minimize worn replacements, then newly filled slots. A proof of unreachability also accounts for known legal unpriced options. A cutoff or unresolved acquisition path limits the conclusion. The UI suspends work off the planner tab and releases unfinished results when it closes. See the [canonical delivery report](reviews/PR-006.md#d-optimization-correctness-and-product-decisions) for proof boundaries and benchmarks.

Max Gear uses the highest verified quality and maximum supported stars in Plan A, with the fewest lower-quality exceptions required to preserve active set thresholds. It chooses the greatest modeled output among those assignments, breaking exact ties in deterministic slot and option order. Plan B raises every worn item to the catalog ceiling and leaves empty slots alone. Max Gear can include legal upgrades with unknown quotes. The UI labels calculable gold and unknown portions separately. It reports the actual modeled result of the quality/star ceiling, which can differ from the Economy output optimum.

The native tooltip extension post-hooks `AZSInspect:RefreshDoll` and the slot's existing `OnEnter` using `hooksecurefunc` and `HookScript`. It appends after the host sets the tooltip owner and validates that the slot matches this world's equipped item. Simulator icons evaluate adjacent changes from the current simulated loadout. Plan icons show separate output and survival differences for the item and the corresponding full-plan results. Attribute gains and pressure decreases use the beneficial color. Attribute losses and pressure increases use the detrimental color. Changes that round to zero use a neutral dash in the delta columns. Tooltip ownership is released on relevant panel, slot, or context changes. Hovering performs no combination search.

## Offline verification

Run the following with Python 3 and Lupa's Lua 5.1 runtime. Supply a trusted, locally accessible `Generated/Content.lua` from the game. The script executes that input as Lua. Use `--source-root` to compare the same data against an earlier checkout or source archive and `--repeat` to smooth CPU timing.

```text
python scripts/verify_reborn_gear.py --native-content <Generated/Content.lua> --repeat 7
python scripts/verify_reborn_gear.py --native-content <Generated/Content.lua> --gear-csv <independent-extraction.csv> --source-root <checkout>
```

The optional UTF-8 CSV has a header. Its first eight columns are tier key, star count, three extraction metadata columns, Warlock main-hand damage as a percentage, eight-armor-piece flat HP, and eight-armor-piece damage as a percentage. Supply values extracted independently of the planner. The verification compares the final three values at a tolerance of 0.00051 in their reported units, allowing a three-decimal reference. The benchmarks compare returned plan pressure and gold with the full public evaluator and check repeatability. Small-space optimum is checked separately by exhaustive enumeration in `tests/test_reborn_gear.lua`. Native game data, local expected CSV, and historical captures remain external.

Public balance data are pinned to `21071e86fee66ca7`. Native contract inspection, offline content comparisons, and the Campaign and Dalaran acquisition observations used Reborn 0.7.4. The full Campaign interaction, native tooltip rendering, and pause behavior of the revised window remain game-verification items.
