# Legacy Reborn gear planner retirement

[Draft PR #8](https://github.com/linicam/survivor-ui-reborn/pull/8) targets `main` at `7d10fc19dd2c0e28da6287210f5b65e23fa5ce66` from `retire-legacy-gear-planner`. The tested implementation is `9a36a64abee2fd05242eaadea30a533fe10c5f91`. The subsequent report commit changes Markdown only. PR #7 is frozen at `92019d37de10dc3b63462cb7f66d126e3a139cf6` and its R18–R31 work is suspended.

## Compatibility decision

The legacy model assumes a deterministic class, slot, tier and star tuple. The inspected Windows 0.8.0 client (installation serial 1795790237) ships both the old 4/8-piece rules and a separate random-item model with instance data and 2/4-piece rules. The presence of the old catalog therefore admits incompatible equipment. The native World router provides a protocol handshake after World entry, and the documented addon API provides no authoritative legacy-equipment compatibility flag. The audit did not establish a reliable World client version signal at addon load. [Official Addon API](https://azreborn.com/guides/addon-api)

`SurvivorUI.toc` is the sole runtime gate. It omits `RebornGear.lua`, `RebornGearModel.lua` and `RebornGearPlanner.lua` for every client. This covers 0.8.0, older installations and missing or unverified future versions. It requires no runtime version parsing or capability probes. The legacy sources remain in the repository and the existing archive format still includes them as inert files. Historical tests explicitly load them. The saved user setting is inert and cannot affect the manifest.

## Entry points and side effects

| Entry or side effect | Disposition |
| --- | --- |
| `/sui gear` and arguments, including `show`, `worn`, `simulator`, `keys`, `on` and `off` | The real slash handler prints a localized suspension message and directs the player to native equipment. The general slash help no longer advertises the feature. |
| Settings | The Global page omits the open button and enable checkbox. The Guide omits legacy Marks and Sets pages on Reborn and retains the original-game page paths. |
| `SurvivorUI_RebornGearEnabled`, `Open`, `Toggle` and `RecordStart` | The manifest prevents the legacy globals from being defined. The general recorder no longer invokes the legacy recording callback. |
| Inspect Upgrades, doll and native tooltips | The legacy module never attaches the button or the `RefreshDoll`, `OnHide`, `OnEnter` or `OnLeave` hooks. Native ownership and tooltips need no cleanup from the retired module on fresh load or reload. |
| Background World work | Legacy `AZSZONE`, `AZSARMOR`, `AZSHELLO`, login and World subscriptions are never installed. Legacy diagnostic and toggle sync requests, planner frames, OnUpdate searches, recommendations and price or pressure calculations are unreachable. Shared native and addon listeners retain their own lifecycle. |
| Baselines and SavedVariables | The retirement path never initializes, reads, migrates, clears or replaces `SurvivorUIDB.rebornGear` or its per-class baselines. The TOC keeps the existing SavedVariables declarations. |

`BuildList.lua`, `CharacterPane.lua`, `RunHistory.lua`, `Jewelry.lua`, `RebornCompat.lua`, `RebornAnalysis.lua`, the analysis model and its map reference remain active. The three retired modules have no other runtime callers. Gear terminology in existing diagnostics distinguishes the run's `AZSGEAR` jewelry snapshot from historical `AZSARMOR` planner observations. The current general recorder still records native jewelry. The original snapshot paths for worn equipment and history, the racial cooldown reader and the boss, Rift and guardian trackers keep their existing contracts. Previous documentation and PR #6 review evidence remain available as historical material.

## Validation

- Lua 5.1 and 5.4 syntax checks passed for 62 Lua files per runtime. Five test suites passed on both runtimes, including 261 compatibility checks per runtime. Five historical replays passed with 63 assertions per runtime.
- The retirement regression covers an 0.8.0-like environment with both catalogs, unknown and missing versions, an existing enabled profile with a baseline, localized slash dispatch, absent Options controls, excluded legacy module loading and a working general recorder with `native_gear`. Manifest exclusion is the invariant that prevents legacy listeners and hooks from being installed. The test uses a mocked environment and does not render the native UI.
- Two negative controls substitute the original `main` manifest and slash handler separately. Under both Lua versions the former fails because the legacy module is listed in the runtime manifest. The latter reaches the legacy Open sentinel and fails. The historical gear suite still loads the old modules explicitly and checks arithmetic, optimizer behavior, simulator, tooltip and lifecycle paths. Its historical recorder test explicitly starts the legacy observation callback.
- The Windows PowerShell diagnostic helper tests passed, covering native GitHub CLI handling, large payload chunking, and diagnostic metadata and manifest checks. The manifest validator passed in the development checkout and for the packaged addon.
- Both ZIPs were built in a separate checkout of `9a36a64` with `bash scripts/package.sh`. Both passed CRC checks. The addon contains the verified `9a36a64` build stamp and excludes the retired scripts from the packaged TOC. The helper archive contains the four expected files.

## Remaining compatibility work

The load-time gate removes the unsafe runtime path without introducing a second equipment model. The next compatibility PR should focus on the records that players continue to see. First verify the source and completeness of Run History's worn armor and loot in 0.8.0. Then correct Character Pane attribution, particularly the documented jewelry meaning of `AZS_STATS.g*`, and preserve the distinction between missing values and zero. Review stale static map references and skill or card tooltip semantics against version-matched evidence in a subsequent scoped change. Preserve the existing event and history behavior wherever the current contract is valid.

No client was launched or modified for this change. A future native smoke check of this draft should use enUS and zhCN in Hub and Campaign, invoke `/sui gear simulator`, inspect the Global page and Guide, and hover an equipped item in native Inspect. Expect a localized message, absent planner controls, and the game's ordinary tooltip. A general diagnostic session should still show native jewelry alongside ordinary run events. This is a smoke check for retirement, with independent review and release acceptance pending. Passing mocks and historical replays support review of this draft. Full 0.8.0 compatibility remains subject to the data findings above.
