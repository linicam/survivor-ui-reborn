## Ownership, schema and reconciliation

- `RebornCompat.lua` still owns run and phase identity, fresh equipment snapshots, ability merge and stale reply rejection, and binds the progression snapshot to its end observation. `RebornDiagnostics.lua` keeps the existing offer listener and command hook and routes each eligible action to progression before checking whether recording is enabled. `RebornAnalysisModel.lua` supplies the existing skill boost parser and shared jewelry change parser. There are no additional game requests or frame-rate samples.
- `RebornProgression.lua` owns the version 1 snapshot. It contains the stable run key, coverage, at most 512 confirmed choices, per-skill rank, display metadata, counts, rarity buckets and current modifier data, plus observed jewelry counts indexed by unique slot and bonus. Each choice stores its selection order, type, key, rarity, level, time and structured evidence. A same-key item reacquired after removal gets a new observed instance generation. Full card hands and temporary attribution data are excluded from saved history. Live choices use memory for the current client session.
- Skill confirmation requires a fresh learned observation with the offered key, spell ID and exact rank. Late tips can enrich the matching selection. Empty or dismissed hands can precede the confirming packet. A repeated command in one hand is coalesced, and distinct choices whose outcome cannot be resolved remain unconfirmed. The skill's damage, targets and area use structured after totals when provided. The verified bond reads its learned values for damage, interval and additional targets. Standard cooldown and duration can be constrained by native floors or caps. A preview for those and other unreconciled codes remains visible with its applied total unavailable. The live tooltip uses native descriptions and current `cdmax` for effective stats and never estimates hit damage, pet inheritance or attack speed.
- Jewelry confirmation reuses scoped native rows and their slot-plus-bonus identity. The offered name, icon and slot match the observed piece, with tuple uniqueness on the worn side. An acquisition requires a new tuple and an established worn baseline. A grow or empower requires a change to the matching piece. For interpreted growth effects, compare the offered delta with the changed individual effect while allowing one-decimal rounding. An ambiguous duplicate or a replacement receives independent coverage. The native effect text remains authoritative.
- `RebornProgressionView.lua` provides the only viewer. It uses the established History button pattern, flat dark theme, scroll frame and slider, addon font, and `UISpecialFrames` registration. Chronological rows place the skill name and rank above selection metadata so long localized names and larger text can wrap independently. `BuildList.lua` reserves a separate right edge for count, using Phase 2 name and effect fitting. Build and History use the existing tooltip paths. `Options.lua` and `Locale_zh.lua` supply the module control and Simplified Chinese text.
- `RunHistory.lua` attaches copied progression to the existing snapshot and settlement paths. The first accepted Campaign victory freezes its copy. If the Endless transition is observed first, the store freezes the current Campaign cut at that transition. Endless carries the live store and adds its own choices. Saved history retains the existing per-phase and retention settings.

## Coverage limits and developer review

- Installation mid-run, reload, missed or ambiguous replies and record eviction can make coverage partial. Up to 12 intents are retained, with a 15-second correlation window from the command. Unconfirmed actions do not contribute a choice. A passive with no matching learned row may remain unconfirmed until an existing ability refresh. An observed same-key item removed and reacquired receives a new count. If a server extension replaces an item with an indistinguishable tuple without an intervening observed removal, confirmation depends on the available effect evidence.
- The accepted 0.8.0 native and public data expose current descriptions and cooldown, with availability varying by ability. Formula recovery beyond verified card totals and the explicit bond values is pending. Late stable snapshots retain effective text as exposed in the original locale. Older history entries have no progression payload and their previous summaries stay usable.
- The production observer, presentation event ordering, settlement and renderer passed host tests. User-facing dates and names in the host layout use test inputs. The local visual comparison uses mocked frames, synthetic timing and substitute font measurement. It verifies layout and text flow. Native rendering, keyboard and mouse delivery, frame stacking, Escape, and actual frame timing require in-game validation.
- No blocking issue remained in the developer's source and host review. Independent review, integrated native acceptance and a separate release decision remain open.

## Integrated native acceptance

Run the main pass in one Warlock Campaign and Endless continuation. Use an Adventure with objective fields and, if practical, the previously reported Isle of Quel'Danas plate case. Lua host tests cover the data and layout boundaries below. Native behavior and accessibility are the remaining checks. [Phase 2 checklist](PR-009.md#remaining-native-validation) [Phase 3 checklist](PR-010.md#integrated-native-acceptance)

1. **While leveling.** With Diagnostics off, open the Build viewer and choose one skill via keyboard in the native style and one with the mouse in Classic. Reroll or skip once and check that no extra choice appears. Include a first acquisition with an affix and a multi-affix card when offered. Switch card styles during spell and jewelry hands and exercise Shift comparison, long text, focus and restoration. Check all affixes, selected rarity and count in the viewer and the existing Build hover. At the Demonic Knowledge interval cap, compare the offered total with the current native tip and the skill's applied total. Keep screenshots of the cards and both tooltips if they differ.
2. **During the same run.** Acquire a ring and then enhance it. Check `+0` followed by `+1`, the full localized and decimal effect on hover and the other ring's independent count. For an amulet, inspect both complete effects and its replacement or empower behavior when offered. At increased scale, open the viewer from Build with other SurvivorUI windows open. Check scroll, collapse, Escape and existing pause behavior. Reload only after recording the uninterrupted result and verify that resumed play reports partial coverage. Repeat a short panel comparison in the other supported locale if language switching requires a separate login.
3. **At the phase change.** At Campaign victory, keep a record and continue immediately into Endless. Confirm that new choices and effects appear only in the Endless snapshot, with prior choices carried forward. Compare both moments' jewelry, armor, final rewards and progression after ending and reloading the end screen. Inspect one pre-Phase 4 entry for the unavailable label. For a discrepancy, capture the run, gear, armor, reward and end update order.
4. **During combat.** Check Classic, Dial and native Tracker ownership with Adventure objectives, Rift and Guardian data and the saved anchor. Check an untargeted Isle of Quel'Danas elite alongside ordinary enemies with ordinary bars disabled, plus an Ahn'Qiraj control if needed. Verify the independent boss and guardian toggles. Switch Nameplates to the game's style, reload, test the existing visibility key and world marks, and switch back to the prior choices. Capture any incorrectly classified unit both untargeted and targeted. Check one recognized curse warning and its ending when available.
5. **Co-op follow-up.** In the smallest available co-op pass, fall and revive once, then finish. Verify that the temporary defeat does not save a history entry and the actual result keeps the matching progress. If an entry appears early, capture `AZSRUN`, `AZSREVIVE` and `AZSEND` ordering.
